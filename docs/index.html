blender-loop

把「用 Blender 反复调模型」变成可复现的工程流程： 参数空间 → 无头渲染 → 量化打分 → 搜索 → 报告。

三个支柱

分别解决不可复现、机器不可控、评估靠眼睛。

① 建模工作流

场景即代码：--factory-startup 从空场景重建，单位/坐标/导出全部显式约定。

② 机器调优

先量后调：冷启动/渲染/布尔基准，地址空间上限、flock 串行、单次超时、峰值 RSS。

machine-tuning.md →

③ 自迭代闭环

评估器契约 + 内容哈希缓存 + 预算 + 坐标下降，产出可离线查看的单文件 HTML 报告。

self-iteration.md →

闭环长什么样

每一轮只做一件事：给一组参数打分，并把证据留下来。

三分钟跑起来

没有 Blender 也能跑测试；跑 demo/bench 才需要真实二进制。

python -m pip install -e ".[dev]"
pytest -q

# 机器基准
blender-loop bench --blender /path/to/blender --out out/bench

# 完整自迭代示例
blender-loop demo  --blender /path/to/blender --out out/demo
open out/demo/report.html

示例结果

隐藏参数 (1.42, 0.74, 0.22)，从 (1.0, 1.0, 0.0) 出发， 20 次评估收敛到 (1.45, 0.716, 0.225)，剪影 IoU 0.953。

报告含迭代曲线、每次评估的表格、目标/最佳渲染对比。

一次机器基准（实测）

headless Ubuntu · 16 核 CPU · 无独显 · Blender 4.2.9 LTS

项目耗时
冷启动（无场景）0.23 s
渲染 1024² / 1 spp0.03 s
渲染 1024² / 16 spp0.26 s
渲染 1024² / 64 spp0.98 s
EXACT 布尔（29k 顶点）0.23 s
454 MB

子进程峰值 RSS。上限默认 8 GiB，用 RLIMIT_AS 在分配阶段失败， 而不是等内核 OOM 把同机器的服务一起带走。

仓库结构

代码是 MIT，模型资产不进仓库，Blender 只作为外部工具调用。

src/blender_loop/
  params.py     参数空间：边界、采样、量化、内容哈希
  search.py     坐标下降 / 随机搜索（预算可中断）
  metrics.py    掩膜 IoU / RMSE / 质心 / 包围盒
  blender.py    受控子进程：RLIMIT_AS、flock、超时
  pipeline.py   Loop：缓存、预算、历史、序列化
  report.py     单文件 HTML（内联 SVG + base64 图片）
  demo.py       剪影自迭代示例
  bench.py      机器基准
tests/          54 个单测（不需要 Blender）
docs/           三篇指南 + 本页
