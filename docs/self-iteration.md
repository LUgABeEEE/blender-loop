# 自迭代闭环：从"看着差不多"到"能量化地更好"

这一篇讲**怎么让模型自己变好**：定义目标 → 参数化 → 评估 → 搜索 → 记录，然后重复。

## 1. 闭环的五件东西

```
        ┌──────────────┐
        │  参数向量 p  │
        └──────┬───────┘
               ▼
        ┌──────────────┐        ┌──────────────┐
        │  评估器 E(p)  │───────>│  分数 + 证据  │
        └──────┬───────┘        └──────┬───────┘
               │                       │
               ▼                       ▼
        ┌──────────────┐        ┌──────────────┐
        │  搜索器更新 p │<───────│  历史 / 缓存  │
        └──────────────┘        └──────────────┘
```

| 组成 | 本项目对应 | 要点 |
|---|---|---|
| 参数空间 | `SearchSpace` / `ParamSpec` | 有边界、有默认值、可量化 |
| 评估器 | 任意 `(params, workdir) -> Evaluation` | 纯函数式、可重放 |
| 分数 | `Evaluation.score` | 单一标量，方向明确（越大越好或越小越好） |
| 搜索器 | `coordinate_descent` / `random_search` | 有预算、可中断 |
| 记录 | `LoopResult` + `render_report` | 每次评估都留痕 |

## 2. 目标函数：把"像"变成数字

剪影任务用 IoU：

```python
metrics = silhouette_metrics(render_mask, target_mask)
score = metrics["iou"]                 # 0..1，越大越好
```

多目标时加权组合，但**权重必须写下来**，并做尺度归一：

```python
score = 0.6 * iou + 0.3 * (1 - normalized_landmark_error) + 0.1 * symmetry
```

几条经验：

- **尺度一致**：不同量纲的指标先归一化（除以目标尺度），否则大数会吃掉小数；
- **方向一致**：统一成"越大越好"或"越小越好"，别混；
- **少而稳**：3–5 个指标足够；指标越多，越容易把噪声当成信号；
- **留出验证**：只用一张参考图优化，本质是过拟合——至少留一组没参与优化的样本做验收。

## 3. 参数空间：能搜，也要能解释

```python
space = SearchSpace([
    ParamSpec("width", 0.4, 2.0, default=1.0),
    ParamSpec("height", 0.3, 1.6, default=1.0),
    ParamSpec("offset_x", -0.6, 0.6, default=0.0),
])
```

- 边界来自物理约束（可打印尺寸、装配间隙），不是"随便给个范围"；
- 参数之间强耦合时，坐标下降会慢——换随机/进化搜索，或先做敏感性分析；
- `quantize(params, 6)` 让"数值上等价"的参数共享缓存，避免重复评估；
- 参数命名用领域语义（`wall_mm`、`ipd_mm`），不要用 `p1`、`p2`。

## 4. 评估器契约

```python
def evaluate(params, workdir) -> Evaluation:
    ...
    return Evaluation(
        params=params,               # 循环会覆盖成量化后的值
        score=score,
        metrics={"iou": ..., "rmse": ...},
        artifacts=[str(png)],
    )
```

- **确定性**：同一组参数必须给同一个分数（否则缓存和复现都失效）；
- **副作用只落在 `workdir`**：不要写仓库、不要改全局状态；
- **失败要显式**：评估器内部 `check()` 抛错，别返回 0 分——0 分会被搜索器当成"合法但很差"；
- **证据落盘**：渲染图、统计 JSON 都进 `artifacts`，报告才能自解释。

## 5. 缓存与预算

- 缓存键 = 量化后参数向量的内容哈希（`SearchSpace.key`）；
- 同一次运行内重复评估 0 开销；`history.json` 可离线重建报告；
- 预算按"新评估次数"计，缓存命中不扣预算；
- 预算耗尽时搜索器抛 `BudgetExhausted`，循环捕获并返回当前最优——不会丢结果。

## 6. 搜索策略

| 策略 | 何时够用 | 代价 |
|---|---|---|
| 坐标下降 | 参数 2–10 个、目标大致单峰 | 每轮 2×参数数 次评估 |
| 随机搜索 | 做基线、估上界 | 与维度无关，但收敛慢 |
| 进化/贝叶斯 | 高维、强耦合、评估昂贵 | 需额外依赖 |

坐标下降的步长从 `span × step_fraction` 开始，每轮乘 `shrink`；
它**不保证全局最优**，所以建议：先用随机搜索撒几十个点做基线，再用坐标下降精修。

## 7. 收敛与停止

三种停止条件，按需组合：

1. **预算**：最可靠，`budget=60`；
2. **阈值**：分数达到验收线即停（在评估器里抛 `BudgetExhausted` 的同构异常，或在循环外判断）；
3. **步长下限**：最小步长小于量化精度时，继续搜也没意义。

报告里要看的不只是 best，还有**曲线形状**：如果 20 次之后还在跳，说明步长太大或目标有多个局部峰。

## 8. 过拟合与验收

- 优化用的参考图 ≠ 验收用的参考图；至少留一张"没参与搜索"的图；
- 参数边界是物理约束，不要为了分数放宽；
- 验收看**多项指标**（IoU + 关键点误差 + 尺度），单看一个分数容易钻空子；
- 记录每次运行的 Blender 版本、参数空间定义、随机种子——复现的前提。

## 9. 报告与复现

```bash
blender-loop demo --blender /path/to/blender --out out/demo
# -> out/demo/history.json（完整历史）
# -> out/demo/report.html（曲线 + 表格 + 目标/最佳对比图）
```

报告是单文件 HTML：内联 SVG 曲线、base64 图片，离线可看，便于贴给别人。
`history.json` 里保存了参数空间定义与每一次评估，足够重放出同一张报告。

## 10. 一个真实的最小闭环

`blender-loop demo` 的流程（不需要任何模型资产）：

1. 用隐藏参数 `width=1.42, height=0.74, offset_x=0.22` 渲染目标剪影；
2. 从默认参数 `(1.0, 1.0, 0.0)` 出发，坐标下降；
3. 每次评估 = 一次 Blender 渲染 + 一次 IoU 计算；
4. 20 次评估后收敛到 `width≈1.45, height≈0.72, offset_x≈0.23`，IoU≈0.95。

这条流程可以直接换成"头壳参数 → 渲染轮廓 → 与设计图比对"，把示例里的球体换成你的几何脚本即可。
